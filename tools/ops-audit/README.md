# ops-audit — 어드민 셸(`ops/index.html`) 자동 검수

```
node tools/ops-audit/route.mjs     # 해시 라우팅 26항목
node tools/ops-audit/session.mjs   # 세션 이어가기·로그아웃 27항목
```

둘 다 저장소를 그대로 정적으로 띄우고, 엣지 함수는 `page.route` 스텁으로 대신한다.
서버도 DB도 필요 없다. 합쳐 7초쯤 걸린다.

## 왜 훅에 없나 — 일부러다

`tools/hooks/pre-push` 에 안 달려 있다. 붙이면 안 되는 이유가 셋이다.

1. **크로미움이 필요하다.** 600MB 이고 `playwright` 패키지의 `scripts` 가 비어 있어
   `npm install` 로는 안 깔린다. 사용자 PC 3대 중 어디에 깔려 있는지 모른다.
2. **랜딩 훅에는 부분 우회가 없다.** career-coach 훅과 달리 `CC_SKIP_HOOK` 이 0곳이다.
   유일한 탈출구가 `git push --no-verify` 인데 그건 **전부 끄는** 스위치다.
3. 그래서 브라우저 없는 PC 에서 한 번 막히면 그 뒤로는 `--no-verify` 를 쓰게 되고,
   그 순간 0겹~2겹 검수가 **통째로 꺼진다.** career-coach/CLAUDE.md 에 같은 일이 이미
   한 번 적혀 있다 — "엄격한 규칙이 우회를 부르면 덜 엄격한 규칙보다 검사량이 적어진다."

이 검사의 자리는 CI 다. 랜딩은 공개 저장소라 GitHub Actions 가 무료다.
(워크플로 얹기는 미완 — `.github/workflows/**` 는 MCP 토큰으로 못 쓴다. 브리지가 붙은 세션에서 한다.)

## 크로미움이 없으면

`건너뜀 — <이유>` 를 찍고 **종료코드 0** 으로 나간다(저장소의 figma-audit 과 같은 규약).
단 `CI` 환경변수가 있으면 **종료코드 1** 이다 — CI 에서 "브라우저가 없어서 조용히 통과" 는
사고다. GitHub Actions 는 `CI=true` 를 알아서 넣으므로 워크플로에 쓸 것이 없다.

경로 탐색 순서: `$CHROMIUM_PATH` → `/opt/pw-browsers/chromium-1194/…` →
`/opt/pw-browsers/chromium/…` → playwright 기본값.

## 이 검사들이 진짜로 무엇을 잡는지 (변이로 확인한 것)

검사가 초록인 것과 검사가 **깨질 수 있는 것**은 다르다. 넣기 전에 `ops/index.html` 을
일부러 망가뜨려 확인했다.

| 망가뜨린 것 | 결과 |
|---|---|
| `renderPage` 의 `history.replaceState` 정규화 제거 | route ❌ 4건 (`주소에 함수 이름이 없다` 포함) |
| 다중 탭 방어 3개 **전부** 제거 (`storage` 리스너 · 갱신 직전 저장소 재읽기 · 401 재시도) | session ❌ 2건 (탭 A 가 세션을 잃는다) |
| 위 3개 중 **하나만** 제거 | 전부 통과 — 셋이 서로를 대신한다 (설계대로다) |

두 가지는 만드는 과정에서 실제로 헛검사였고, 고친 뒤 위 표가 됐다.
- `주소에 함수 이름이 없다` 를 스크립트 **맨 끝**에 두면 그 자리 주소에는 애초에 함수 이름이
  없어서 무엇을 깨도 초록이었다. 옛 딥링크로 들어간 **직후**로 옮겼다.
- `/auth/refresh` 스텁이 본문의 `refresh_token` 을 안 보고 매번 같은 `A2` 를 돌려주면,
  회전으로 서로를 죽이는 사고가 스텁 안에서 **일어날 수 없다.** 이제 낡은 갱신 토큰은 401 이고
  액세스 토큰도 같이 회전한다. 그리고 희생자는 **탭 A** 다 — 탭 B 만 보면 못 잡는다(B 는
  그 뒤 스스로 갱신해 값을 되살려 놓는다).

## 포트

정적 서버는 포트 `0`(임의 할당)으로 연다. 고정 포트로 두면 다른 세션이 같은 포트를
잡고 있을 때 `EADDRINUSE` 로 프로세스가 죽는다(실측). 셋을 동시에 돌려도 안 부딪힌다.
