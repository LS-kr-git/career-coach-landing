# ops-audit — 어드민 셸(`ops/index.html`) 자동 검수

```
node tools/ops-audit/route.mjs     # 해시 라우팅
node tools/ops-audit/session.mjs   # 세션 이어가기·로그아웃
node tools/ops-audit/nav.mjs       # 왼쪽 탭바 (선택 표시 · 묶음 위계 · 폭 · 탭 제목)
```

셋 다 저장소를 그대로 정적으로 띄우고, 엣지 함수는 `page.route` 스텁으로 대신한다.
서버도 DB도 필요 없다. 합쳐 10초쯤 걸린다.

## 왜 훅에 없나 — 일부러다

`tools/hooks/pre-push` 에 안 달려 있다. 붙이면 안 되는 이유가 셋이다.

1. **크로미움이 필요하다.** 600MB 이고 `playwright` 패키지의 `scripts` 가 비어 있어
   `npm install` 로는 안 깔린다. 사용자 PC 3대 중 어디에 깔려 있는지 모른다.
2. **랜딩 훅에는 부분 우회가 없다.** career-coach 훅과 달리 `CC_SKIP_HOOK` 이 0곳이다.
   유일한 탈출구가 `git push --no-verify` 인데 그건 **전부 끄는** 스위치다.
3. 그래서 브라우저 없는 PC 에서 한 번 막히면 그 뒤로는 `--no-verify` 를 쓰게 되고,
   그 순간 0겹~2겹 검수가 **통째로 꺼진다.** career-coach/CLAUDE.md 에 같은 일이 이미
   한 번 적혀 있다 — "엄격한 규칙이 우회를 부르면 덜 엄격한 규칙보다 검사량이 적어진다."

이 검사의 자리는 CI 다. 랜딩은 공개 저장소라 GitHub Actions 가 무료다.
워크플로는 `.github/workflows/ops-audit.yml` 이다 — `ops/**` · `tools/ops-audit/**` ·
`assets/supabase-config.js`(셸이 import 하는 파일) 가 바뀐 푸시·PR 에서만 돈다.

## 크로미움이 없으면

`건너뜀 — <이유>` 를 찍고 **종료코드 0** 으로 나간다(저장소의 figma-audit 과 같은 규약).
단 `CI` 환경변수가 있으면 **종료코드 1** 이다 — CI 에서 "브라우저가 없어서 조용히 통과" 는
사고다. GitHub Actions 는 `CI=true` 를 알아서 넣으므로 워크플로에 쓸 것이 없다.

경로 탐색 순서: `$CHROMIUM_PATH` → `/opt/pw-browsers/chromium-1194/…` →
`/opt/pw-browsers/chromium/…` → playwright 기본값.

## 이 검사들이 진짜로 무엇을 잡는지 (변이로 확인한 것)

검사가 초록인 것과 검사가 **깨질 수 있는 것**은 다르다. 넣기 전에 `ops/index.html` 을
일부러 망가뜨려 확인했다.

| 망가뜨린 것 | 결과 |
|---|---|
| `renderPage` 의 `history.replaceState` 정규화 제거 | route ❌ 4건 (`주소에 함수 이름이 없다` 포함) |
| 다중 탭 방어 3개 **전부** 제거 (`storage` 리스너 · 갱신 직전 저장소 재읽기 · 401 재시도) | session ❌ 2건 (탭 A 가 세션을 잃는다) |
| 위 3개 중 **하나만** 제거 | 전부 통과 — 셋이 서로를 대신한다 (설계대로다) |
| 폭 예약 `nav a[data-t]::after` 제거 | nav ❌ 1건 (폭이 230↔237 로 튄다) |
| `white-space:nowrap` 제거 | nav ❌ 1건 (**접힘은 안 난다** — 위 표 참고) |
| `max-width` 320 → 150 (조임) | nav ❌ 2건 (칸 8개의 글자가 잘린다) |
| `aria-current` 설정 제거 | nav ❌ 2건 |
| `scrollIntoView` 제거 | nav ❌ 1건 (짧은 화면에서 선택 칸이 336px 아래로 밀려난다) |
| `nav a:focus-visible{outline:none}` 을 넣음 | nav ❌ 1건 (포커스 표시가 죽는다) |
| `*{outline:0}` 전역 리셋을 넣음 | nav ❌ 1건 (같은 자리 — 리셋 CSS 로 조용히 뒤집히는 길) |
| `nav a:focus-visible{outline:2px solid …}` 로 **우리 색을 덮어씀** | nav ❌ 1건 (기본값을 쓰기로 한 결정이 뒤집힌다) |
| 호버 규칙에서 `:not(.on)` 제거 | nav ❌ 1건 (선택된 칸에 배경이 생긴다) |
| `document.title` 갱신 제거 | nav ❌ 1건 |
| 로딩 표시를 빈 문자열로 되돌림 | nav ❌ 1건 |
| 계정 블록 `padding-left` 12 → 18 | nav ❌ 1건 (정렬선이 셋으로 갈라진다) |
| 선택 상태에 배경색 부활 | nav ❌ 2건 |
| `scrollbar-gutter:stable` 제거 | nav ❌ 1건 — **다만 규칙이 사라진 것만 잡는다** (아래) |

검사 파일(스텁) 쪽을 망가뜨려 본 것도 적어 둔다 — 검사가 스스로를 얼마나 지키는지다.

| 망가뜨린 것 | 결과 |
|---|---|
| `route.mjs` 의 `/view/([^/]+)` 을 `([a-z]+)` 로 좁힘 | route ❌ **26항목 전부** (`#t` 가 안 생겨 타임아웃) |
| `route.mjs` ⑪ 의 옛 딥링크 대상만 NAV 에 없는 id 로 (`…/s02` → `…/zz9`) | route ❌ 2건 — 첫 화면으로 떨어진다 |

네 가지는 만드는 과정에서 실제로 헛검사였고, 고친 뒤 위 표가 됐다.
- `주소에 함수 이름이 없다` 를 스크립트 **맨 끝**에 두면 그 자리 주소에는 애초에 함수 이름이
  없어서 무엇을 깨도 초록이었다. 옛 딥링크로 들어간 **직후**로 옮겼다.
- `/auth/refresh` 스텁이 본문의 `refresh_token` 을 안 보고 매번 같은 `A2` 를 돌려주면,
  회전으로 서로를 죽이는 사고가 스텁 안에서 **일어날 수 없다.** 이제 낡은 갱신 토큰은 401 이고
  액세스 토큰도 같이 회전한다. 그리고 희생자는 **탭 A** 다 — 탭 B 만 보면 못 잡는다(B 는
  그 뒤 스스로 갱신해 값을 되살려 놓는다).

- `nav.mjs` 의 「두 줄이 되지 않는다」 는 **절대 못 깨지는 검사였고, 지금은 없다.** 두 번 틀렸다.
  처음에는 `nav{white-space:nowrap}` 때문에 접히지 않는다고만 보고 높이 검사를 남겼는데,
  검사관이 재 보니 **nowrap 을 풀어도 접히지 않았다** — 탭바가 `max-content` 라 폭이 최장 칸에
  맞춰지기 때문이다. 접히려면 `nowrap` 해제 **와** `max-width` 조임이 **동시에** 나야 한다.
  단일 고장으로 도달할 수 없는 검사는 검사가 아니라 장식이라 지웠다. 그 공간은 둘이 덮는다 —
  넘침은 `scrollWidth > clientWidth`(잘림), nowrap 해제는 `white-space` 항목.

  | 상태 | navW | 잘린칸 | 접힌칸 |
  |---|---|---|---|
  | 정상 (max-width 320 · nowrap) | 237 | 0 | 0 |
  | 짧은 화면(420px) | 237 | 0 | 0 |
  | `max-width` 150 | 151 | **8** | 0 |
  | `nowrap` 제거 | 237 | 0 | **0** ← 그래서 지웠다 |
  | `nowrap` 제거 + `max-width` 150 | 151 | 0 | 12 |
- `nav.mjs` 의 `login()` 은 `#main h1` 이 아니라 **`#main h1#t`** 를 기다린다. 셸의 오류 화면도
  `<h1>화면을 불러오지 못했습니다</h1>` 라서, 스텁 경로가 어긋나면 항목들이 **오류 화면을 상대로**
  재고도 전부 초록일 수 있었다. `#t` 는 이 스텁만 붙이는 표식이다.
- **세 파일의 스텁 화면 이름은 전부 가짜다** (`s01`~`s14` · `가나다 라마바` 꼴).
  `ops/index.html` 이 "여기에 화이트리스트를 두지 마라 — 두는 순간 화면 목록이 공개 저장소에
  박힌다" 고 정해 뒀고, 이 저장소는 공개다. 검사에 필요한 것은 이름의 뜻이 아니라
  성질(가장 긴 칸 하나 · 칸 14개 · 묶음 여럿 · 해시가 도는가)뿐이다.
  - `route.mjs`·`session.mjs` 는 2026-08-13 까지 진짜 id 셋을 썼고, **제목은 그 사이 바뀐
    이름을 안 따라가 이미 안 쓰는 옛 값이었다.** 새는 것보다
    "읽는 사람이 진짜인지 스텁인지 구별할 수 없는 상태" 가 더 나빠서 같이 가짜로 바꿨다.
  - **함수 이름(`ops-1udm1xmi`)만은 진짜를 쓴다.** 셸이 `FN` 상수로 이 접두사를 떼는지를
    재는 검사라 다른 문자열을 넣으면 그 갈래를 아예 안 지난다. 그리고 새는 것도 아니다 —
    같은 공개 저장소 `ops/index.html` 에 `const FN` 으로 이미 박혀 있다.
  - ⚠️ **스텁 라우터의 정규식을 글자 종류로 좁히지 마라** — `route.mjs` 는 `/view/([^/]+)` 다.
    한때 `[a-z]+` 였고, 스텁 id 를 `s01` 로 바꾸는 순간 갈래가 통째로 안 맞아 **26항목이
    전부 죽었다**(변이로 재현). 넓혀 두면 이 함정 자체가 없다 — 여기가 하는 일은
    "화면 요청인가" 를 가르는 것뿐이고, 어떤 id 가 올지는 스텁의 `NAV` 가 정한다.

### 🔴 잴 수 없는 것 하나 — `scrollbar-gutter:stable`

이 규칙의 **효과**(스크롤바가 생겨도 탭바 폭이 그대로다)는 여기서 못 잰다.
headless 크로미움은 **오버레이 스크롤바**라 스크롤바가 자리를 안 먹어서, 규칙을 빼도
긴 화면과 짧은 화면의 폭이 똑같이 나온다(둘 다 225). `::-webkit-scrollbar{width:15px}` 로
클래식을 흉내 내 봐도 안 바뀐다 — 그것도 확인했다.

자리를 실제로 먹는 것은 사용자 PC 의 윈도우 크롬이다(실측 15px). 거기서는 이 규칙이 없으면
**화면이 짧은 PC 에서만** 탭바가 223 으로 줄어 가장 긴 칸이 두 줄이 된다 — 재현이 안 되는
버그의 전형이다. 그래서 `nav.mjs` 는 효과 대신 `getComputedStyle(nav).scrollbarGutter` 를 본다.
**잴 수 없는 것을 잰 척하지 않는다** — 규칙이 조용히 사라지는 것만 막고, 그 사실을 항목
이름에 적어 둔다(`효과는 이 환경에서 못 잼`).

## 포트

정적 서버는 포트 `0`(임의 할당)으로 연다. 고정 포트로 두면 다른 세션이 같은 포트를
잡고 있을 때 `EADDRINUSE` 로 프로세스가 죽는다(실측). 셋을 동시에 돌려도 안 부딪힌다.
